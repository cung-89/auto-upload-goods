# Python 商品复制

## 桌面通用入口

双击桌面的 `淘宝商品复制与上架.bat`，或项目根目录的 `启动商品复制工具.bat`。

1. 输入商品链接、目标店铺名称和完整类目路径（与淘宝页面路径一致，用 `>` 分隔）。
2. 加载 `python_copy/shop.example.json`，按实际情况修改品牌、库存、发货地、运费模板、发货时限和售价规则。保存店铺配置不会混入商品标题或 SKU ID。
3. 类目属性填写 JSON，如 `{"产地":"中国大陆","省份":"广西壮族自治区","城市":"防城港市","包装方式":"食用农产品"}`。这只是来源样本的部分属性示例，不代表适用于其他商品。缺项会在日志中列出。
4. 可指定图片序号、自有详情文字及 SKU 改名/排除/改价规则。默认主图前5张，详情为标题加所选主图；不会自动复制来源全部详情，也不会去除图片中的店名品牌。售价为来源价 × 倍率 + 加价，指定 SKU 价格优先。
5. 点击“仅填写检查”或“填写并自动上架”。后者会在校验通过后直接提交，不再二次确认。日志窗口中按提示登录并回车继续；检查完成前不要关闭窗口。

按店铺使用独立登录目录 `.shop-profiles`。任务配置和结果在 `output/task-configs`、`output/tasks`。同店铺同来源的提交会创建不可重复的 `submission.json`；结果不明必须人工核对后台，不能删除记录后盲目重试。

通用入口已实现，但当前仅在番薯真实编辑页核对属性发现，未完成新入口跨类目端到端发布测试。遇到不支持的属性、SKU 控件或采集页面会停止，不保证所有淘宝/天猫类目适用。提交后的平台成功提示、商品链接和前台标题会记录；前台规格、价格、物流及详情仍需核对，报告会标明待核验。

以下为原样本入口，仍只填表、不发布；与桌面“填写并自动上架”不同。

独立 Python 实现，不依赖谋臣界插件。实现商品采集、SKU 转换、图片下载和淘宝编辑页填写；没有保存或提交动作。

已完成本样本从脱敏快照到真实卖家编辑页的 Python 串行运行：8 个 SKU、库存、包邮模板、2 张主图和简版详情均已回读核对。13 项数据测试通过。重新在线采集加填表的整个串行入口、其他商品和其他类目尚未完成验证。

## 运行

在项目根目录执行：

```powershell
python -m pip install -r python_copy/requirements.txt
python -X utf8 python_copy/copy_product.py --snapshot output/python-copy/745182817868/source-snapshot.json --draft
```

重新采集后填写：

```powershell
python -X utf8 python_copy/copy_product.py "https://item.taobao.com/item.htm?id=745182817868" --draft
```

首次需本人登录或验证，之后复用 `.python-copy-profile`。请核对目标店铺。程序执行后保持浏览器打开，终端按回车才关闭；未保存的编辑内容关闭后可能丢失。

配置在 `target-settings.json`。其中的 SKU ID、图片序号、标题和详情针对本样本，换商品必须调整；不是任意商品通用的一键复制工具。采集适配已观察到的淘宝 SSR 页面，天猫其他布局尚未实测。

## 核对

程序匹配实际 SKU 组合，不生成笛卡尔积。缺失价格、重复组合、未知属性或改名导致规格合并时停止。来源展示库存不作为目标库存。

成功输出 `output/python-copy/745182817868/draft-verification.json` 和 `draft-filled.png`，异常输出 `draft-error.png`。请核对文件时间，旧报告只能证明当时的运行。

外包装、品种、系列等类目属性，以及发货时限、平台服务承诺仍需人工核对。本程序不自动提交，不代表已经发布。
